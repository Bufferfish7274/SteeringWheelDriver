4.0 将主控 CAN 控制报文从单轮独立发送改为每两个舵轮共享一帧。本次变更用于缩短四个舵轮接收目标时的时序差，同时保持现有安全状态机、GM6020 与 VESC 控制逻辑、串口遥测列序和 Keil Watch 调参路径不变。

注意，主控需要进行相应的修改，以适应现在的通信协议。

# 版本构建思路

主控控制循环运行在 200 Hz。旧协议为每个舵轮安排一个独立控制帧，当四个控制帧由同一发送循环依次排队时，首个和末个舵轮的目标到达时刻会明显不同（15ms左右时间差）。4.0 把舵轮 1/2 和 3/4 分别组成一组，使四个轮目标可以由两个组控制帧承载，把时间差压缩到5ms左右。

由于控制帧修改，心跳帧也相应地变为舵轮 1/2 和 3/4 分别组成一组。其余部分保持不变。

# 系统结构

```text
主控板
  │ CAN2：0x101/0x102 组控制 / 0x111/0x112 组心跳
  ▼
轮 1/2 分控                         轮 3/4 分控
  ├─ MasterCan：组 ID、槽位、状态      ├─ MasterCan：组 ID、槽位、状态
  ├─ ProductionController              ├─ ProductionController
  ├─ GM6020 + VESC                     ├─ GM6020 + VESC
  └─ Telemetry / LEDs                  └─ Telemetry / LEDs
```

主控通过 CAN2 广播两个组控制帧和两个组心跳帧。每个分控板只通过BSP 过滤器接收自己所属的组，再从固定槽位读取本轮目标。接收后的数据继续进入现有控制链路：

```text
主控组目标
  → 坐标映射
  → AngleOpt 选择最终舵向与 ERPM 符号
  → SetpointRamp + GM6020 位置控制
  → VESC 内置速度环
```

组控制帧只在组内任一目标发生变化时发送，但帧内必须同时包含两个轮的当前目标。目标不变时，主控持续发送组心跳即可维持链路。

# 主控 CAN 协议

## 组映射

轮号到组号的映射为：

```text
group = (wheel_id + 1) / 2
control_id = 0x100 + group
heartbeat_id = 0x110 + group
```

| 舵轮 | 组号 | 控制 ID | 心跳 ID | 帧内槽位 |
| ---: | ---: | ---: | ---: | --- |
| 1 | 1 | `0x101` | `0x111` | `Data[0..3]` |
| 2 | 1 | `0x101` | `0x111` | `Data[4..7]` |
| 3 | 2 | `0x102` | `0x112` | `Data[0..3]` |
| 4 | 2 | `0x102` | `0x112` | `Data[4..7]` |

## 控制帧

控制帧为标准数据帧，DLC 8。每个轮目标占四个字节：

| 字节 | 内容 |
| --- | --- |
| 槽位首字节 | 大端 `int16 ERPM` 高字节 |
| 槽位第二字节 | 大端 `int16 ERPM` 低字节 |
| 槽位第三字节 | 大端 `uint16` 角度码高字节 |
| 槽位第四字节 | 大端 `uint16` 角度码低字节 |

轮 1/3 使用前四字节，轮 2/4 使用后四字节。ERPM 合法范围为
`-32768..32767`，角度码合法范围为 `0..16383`。

例如轮 1 的 ERPM 为 `-1234`、角度码为 `8192` 时，十六进制值分别为
`0xFB2E` 和 `0x2000`，组 1 控制帧的前四字节为：

```text
Data[0..3] = FB 2E 20 00
```

后四字节继续承载轮 2 的当前目标。

## 心跳帧

- 标准数据帧，DLC 8；
- 轮 1/2 使用 `0x111`，轮 3/4 使用 `0x112`；
- 负载不参与控制；
- 建议主控每 80 ms 发送一次。

组控制帧和组心跳都会刷新本组链路时间。主控处理一轮目标更新时，应尽量连续发送 `0x101` 和 `0x102`，以缩短两个控制组之间的时序差。分控固件只能保证正确解码本组槽位，实际四轮同步误差仍需在主控发送端和整车轮组台架上测量。

# 测试与验证

## 主机测试

`Tests/MasterCan` 覆盖：

- 轮 1/2 映射到 `0x101/0x111`；
- 轮 3/4 映射到 `0x102/0x112`；
- 四个轮号的前后槽位选择；
- `int16` 最小/最大 ERPM；
- 角度码 `0`、`8192`、`16383`、`16384` 和 `0xFFFF`；
- 错误组 ID、扩展帧、远程帧和错误 DLC；
- 任一有效组控制帧刷新两轮控制可用状态；
- 组心跳、500 ms 边界、故障恢复和时间回绕。

`Tests/App` 使用组控制帧验证正式构建中的主控接收、目标刷新和GM6020/VESC 调用链。调试构建和正式构建继续分别运行。

测试方法和先前版本一样。
