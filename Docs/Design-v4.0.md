4.0 将主控 CAN 控制报文从单轮独立发送改为每两个舵轮共享一帧。
本次变更用于缩短四个舵轮接收目标时的时序差，同时保持现有安全状态机、
GM6020 与 VESC 控制逻辑、串口遥测列序和 Keil Watch 调参路径不变。

主控发送固件必须与四个分控同步升级。旧单轮协议不能与 4.0 协议混合运行。

## 1. 设计目标

主控控制循环运行在 200 Hz。旧协议为每个舵轮安排一个独立控制帧，
当四个控制帧由同一发送循环依次排队时，首个和末个舵轮的目标到达时刻
会明显不同。4.0 把舵轮 1/2 和 3/4 分别组成一组，使四个轮目标可以由
两个组控制帧承载。

本版本遵循以下约束：

1. 控制帧继续使用标准数据帧、1 Mbps 波特率和 DLC 8；
2. 每组控制两个舵轮，组内两轮共享一个控制 ID 和一个心跳 ID；
3. 每个舵轮仍保留独立的 ERPM 和角度目标；
4. ERPM 使用完整 `int16` 范围，不在接收端额外限幅；
5. 角度码继续使用 `0..16383`，越界值夹紧到 `16383`；
6. GM6020、VESC、AngleOpt、SetpointRamp、PID 和安全状态机不改变；
7. 不增加分控板向主控发送的状态帧或应答帧。

## 2. 系统结构

```text
主控板
  │ CAN2：0x101/0x102 组控制 / 0x111/0x112 组心跳
  ▼
轮 1/2 分控                         轮 3/4 分控
  ├─ MasterCan：组 ID、槽位、状态      ├─ MasterCan：组 ID、槽位、状态
  ├─ ProductionController              ├─ ProductionController
  ├─ GM6020 + VESC                     ├─ GM6020 + VESC
  └─ Telemetry / LEDs                  └─ Telemetry / LEDs
```

主控通过 CAN2 广播两个组控制帧和两个组心跳帧。每个分控板只通过
BSP 过滤器接收自己所属的组，再从固定槽位读取本轮目标。接收后的数据
继续进入现有控制链路：

```text
主控组目标
  → 坐标映射
  → AngleOpt 选择最终舵向与 ERPM 符号
  → SetpointRamp + GM6020 位置控制
  → VESC 内置速度环
```

组控制帧只在组内任一目标发生变化时发送，但帧内必须同时包含两个轮的
当前目标。目标不变时，主控持续发送组心跳即可维持链路。

## 3. 主控 CAN 协议

### 3.1 组映射

轮号到组号的映射为：

```text
group = (wheel_id + 1) / 2
control_id = 0x100 + group
heartbeat_id = 0x110 + group
```

| 舵轮 | 组号 | 控制 ID | 心跳 ID | 帧内槽位 |
| ---: | ---: | ---: | ---: | --- |
| 1 | 1 | `0x101` | `0x111` | `Data[0..3]` |
| 2 | 1 | `0x101` | `0x111` | `Data[4..7]` |
| 3 | 2 | `0x102` | `0x112` | `Data[0..3]` |
| 4 | 2 | `0x102` | `0x112` | `Data[4..7]` |

### 3.2 控制帧

控制帧为标准数据帧，DLC 8。每个轮目标占四个字节：

| 字节 | 内容 |
| --- | --- |
| 槽位首字节 | 大端 `int16 ERPM` 高字节 |
| 槽位第二字节 | 大端 `int16 ERPM` 低字节 |
| 槽位第三字节 | 大端 `uint16` 角度码高字节 |
| 槽位第四字节 | 大端 `uint16` 角度码低字节 |

轮 1/3 使用前四字节，轮 2/4 使用后四字节。ERPM 合法范围为
`-32768..32767`，角度码合法范围为 `0..16383`。

目标角推导公式保持不变：

```text
target_angle_deg = angle_code * 360 / 16384
```

例如轮 1 的 ERPM 为 `-1234`、角度码为 `8192` 时，十六进制值分别为
`0xFB2E` 和 `0x2000`，组 1 控制帧的前四字节为：

```text
Data[0..3] = FB 2E 20 00
```

后四字节继续承载轮 2 的当前目标。

### 3.3 心跳帧

- 标准数据帧，DLC 8；
- 轮 1/2 使用 `0x111`，轮 3/4 使用 `0x112`；
- 负载不参与控制；
- 建议主控每 80 ms 发送一次。

组控制帧和组心跳都会刷新本组链路时间。主控处理一轮目标更新时，
应尽量连续发送 `0x101` 和 `0x102`，以缩短两个控制组之间的时序差。
分控固件只能保证正确解码本组槽位，实际四轮同步误差仍需在主控发送端
和整车轮组台架上测量。

## 4. 接收与状态管理

`MasterCan::init()` 根据 `wheel_id` 生成控制 ID 和心跳 ID，并保留
链路超时配置。`MasterCan::onRx()` 只接受标准数据帧、DLC 8 和本组 ID，
随后根据 `(wheel_id - 1) % 2` 选择本轮槽位。

接收层执行以下校验：

- 其他组控制帧和其他组心跳不会刷新本轮链路；
- 扩展帧、远程帧和错误 DLC 被忽略；
- ERPM 使用显式字节移位解码，不依赖主机字节序；
- 角度码按无符号 16 位读取，超过 `0x3FFF` 时夹紧到 `0x3FFF`。

### 4.1 持久命令语义

```text
control_seen = 当前有效链路周期内是否收到过控制目标
link_valid   = 控制帧或心跳是否仍在配置的超时窗口内
```

任一有效的本组控制帧都会刷新同组两个轮的 `control_seen`，即使本轮
槽位值与上一帧相同。这是因为组帧始终携带本轮当前目标，也是故障恢复
和两轮同步的基础。

| `link_valid` | `control_seen` | 整轮行为 |
| ---: | ---: | --- |
| 0 | 0 | 链路故障，GM6020 与 VESC 失能 |
| 1 | 0 | 等待新控制帧，执行器保持失能 |
| 1 | 1 | 可执行持久目标，同时要求两个执行器在线 |

### 4.2 超时与恢复

默认链路超时窗口为 500 ms：

1. 控制帧同时刷新控制时间戳和心跳时间戳；
2. 链路超时后清除 `control_seen`；
3. 最后 ERPM、角度码和目标角保留，用于遥测与诊断；
4. 单独的心跳只能恢复 `link_valid`，旧目标不会自动复活；
5. 必须收到新的本组控制帧，才能恢复 `control_seen`。

所有时间差使用 `uint32_t` 无符号减法计算，因此支持毫秒时间戳自然回绕。

## 5. 模块实现边界

| 模块 | 4.0 行为 |
| --- | --- |
| `MasterCan` | 组 ID 映射、槽位选择、ERPM/角度解码、控制与链路状态 |
| `BspCan` | CAN2 精确过滤本组控制 ID 和心跳 ID，接口签名不变 |
| `WheelApp` | 本组有效控制帧置位 `control_pending`，其余安全路径不变 |
| `ProductionController` | 消费持久目标，继续执行映射、AngleOpt、斜坡和下发 |
| `Telemetry` | 27 列顺序和字段含义保持不变 |

`MasterCan::Config`、`init()` 和 `onRx()` 的公开接口没有变化。
分控板仍通过 `wheel_id` 配置自身身份，由模块内部推导组号与槽位。

正式固件继续只启动 CAN1 和 CAN2；调试固件仍只启动 CAN1。
本次不改变执行器在线窗口、整轮使能条件、遥测内容和调试输入。

## 6. 安全与上线约束

正式固件只有在以下条件同时成立时才允许整轮动作：

- 主控 `link_valid=1`；
- 主控 `control_seen=1`；
- GM6020 在 20 ms 窗口内在线；
- VESC 在 100 ms 窗口内在线。

任一条件失效时，GM6020 和 VESC 同时失能并持续输出零目标。
执行器恢复后仍需要新的本组控制帧，旧目标不会自动恢复。

上线时必须遵守以下约束：

1. 主控发送固件与四个分控固件同步升级；
2. `0x101` 和 `0x102` 的含义已经改变，不能自动区分新旧控制帧；
3. 每个分控的 `MasterWheelId` 必须与实际舵轮编号一致；
4. 主控组帧必须写入同组两个轮的当前目标，不能只更新变化的一侧；
5. 旧的单轮 `0x101..0x104` 控制协议不再兼容；
6. 所有 CAN 节点继续使用 1 Mbps，并保留总线终端电阻和共地连接。

## 7. 测试与验证

### 7.1 主机测试

`Tests/MasterCan` 覆盖：

- 轮 1/2 映射到 `0x101/0x111`；
- 轮 3/4 映射到 `0x102/0x112`；
- 四个轮号的前后槽位选择；
- `int16` 最小/最大 ERPM；
- 角度码 `0`、`8192`、`16383`、`16384` 和 `0xFFFF`；
- 错误组 ID、扩展帧、远程帧和错误 DLC；
- 任一有效组控制帧刷新两轮控制可用状态；
- 组心跳、500 ms 边界、故障恢复和时间回绕。

`Tests/App` 使用组控制帧验证正式构建中的主控接收、目标刷新和
GM6020/VESC 调用链。调试构建和正式构建继续分别运行。

2026-11-11 验证结果：7 组主机测试全部通过。

### 7.3 板级验收

1. 主控断开时上电，确认 `link_valid=0`、`control_seen=0`，执行器保持失能。
2. 连接组心跳，确认本组链路灯点亮，但 `control_seen` 仍为 0。
3. 发送本组控制帧，按轮号检查槽位、ERPM 符号、角度码和目标角。
4. 只改变组内另一个轮的目标，确认本轮目标不被覆盖且控制可用状态保持。
5. 保持目标不变超过 1 秒，确认控制帧变旧不会导致目标失效。
6. 断开主控，确认约 500 ms 后链路和控制可用状态清零，最后目标仍保留。
7. 恢复组心跳，确认控制仍不可用；再发送本组控制帧，确认整轮恢复。
8. 在四轮台架上分别修改两个组的目标，记录组间和轮间接收时序。

板级验收通过前，不应把主机测试当作四轮同步性能的最终证明。

## 8. 兼容性与后续工作

本版本保留了 3.0 的控制算法、调试模式和遥测接口，主要变化限于
主控接收协议。1.0、2.0 和 3.0 文档继续作为历史版本保留。

仓库外的主控发送实现不在本工程范围内。主控工程需要按本说明完成：

- 两个组控制帧的组帧和连续发送；
- 两个组心跳；
- 组内两个轮当前目标的同步维护；
- 主控固件与分控固件的同版本发布。
