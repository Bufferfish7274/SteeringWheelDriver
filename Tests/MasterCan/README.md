# 主控 CAN 模块测试

本目录包含 `MasterCan` 的主机端测试。实机主控联调使用正式固件，
调试固件不启动 CAN2。

## 协议

- 控制帧：标准帧 `0x100 + group`，DLC 8，其中一个组控制两个舵轮；
  - 每个轮槽为 4 字节：大端 `int16 ERPM` + 大端角度码；
  - `Data[0..3]`：1/3 号舵轮；
  - `Data[4..7]`：2/4 号舵轮；
  - ERPM 范围为 `-32768..32767`；
  - 角度码合法范围为 `0..16383`。
- 心跳帧：标准帧 `0x110 + group`，DLC 8，负载不参与控制。
- 轮 1/2 使用组 1，轮 3/4 使用组 2。
- 本次板级测试使用轮号 1：
  - 控制帧 `0x101`；
  - 心跳帧 `0x111`。

主控每 80 ms 发送组心跳；组内任一轮 ERPM 或角度目标变化时发送组控制帧，
帧内同时携带同组两个轮的当前目标。

## 命令与链路语义

- 收到控制帧后，ERPM、角度码和目标角持续有效，不会因控制帧本身变旧而失效。
- 任一有效的本组控制帧都会刷新两个轮的 `control_seen`，即使本轮槽位值
  没有变化。
- `link_valid` 由本组控制帧或组心跳维持，当前有效期由
  `APP_MASTER_LINK_TIMEOUT_MS` 配置，默认为 500 ms。
- 最终应用应使用 `control_seen && link_valid` 判断目标是否可执行。
- 链路超时后清除 `control_seen`，但保留最后一次解码值供串口观察。
- 链路恢复时，单独的心跳帧只能恢复 `link_valid`；必须收到新的控制帧才能恢复 `control_seen`。

因此，主控保持目标不变时只需持续发送心跳，不需要周期重发控制帧。

## 板级接线

| 信号 | 连接 |
|---|---|
| 主控 CAN_H/CAN_L | 分控板 CAN2_H/CAN2_L |
| 主控 GND | 分控板 GND |
| USB-TTL RX | PA9（USART1_TX） |
| USB-TTL GND | 分控板 GND |

CAN2 使用 PB12/PB13，波特率为 `1 Mbps`。轮 1 固件只接收 `0x101` 和
`0x111`；轮 3 固件只接收 `0x102` 和 `0x112`。总线两端各接 `120 Ω`
终端电阻。

## LED

正式固件中的 PB4 表示 `link_valid`。其余 LED 分别表示执行器在线和整轮
使能，完整定义见项目根目录 README。

## UART 遥测

正式固件的 27 列 FireWater 遥测包含目标 ERPM、角度码、链路状态以及
控制帧/心跳帧年龄，通道定义见项目根目录 README。

## 主机端测试

运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\Tests\MasterCan\host\run.ps1
```

覆盖内容包括：

- 轮号 1 和 4 的 ID；
- 大端 ERPM 和角度码解码；
- 角度码边界处理；
- 标准帧、数据帧和 DLC 8 校验；
- 控制帧建立持久目标；
- 心跳维持 `link_valid`；
- 500 ms 链路边界；
- 链路超时清除 `control_seen` 并保留最后目标；
- 心跳恢复但不恢复旧目标；
- 新控制帧恢复目标；
- 毫秒时间戳回绕。

## 板级测试步骤

1. 不连接主控，烧录并上电，确认 LED 自检后 PB4 心跳，PB5/PB6 熄灭。
2. 串口应显示 `link_valid=0`、`control_seen=0`。
3. 连接主控 CAN2，确认 PB5 点亮，心跳帧计数约每秒增加 12–13 次。
4. 在主控修改组内任一轮的 ERPM 或角度目标，确认每轮只增加一个控制帧计数。
5. 检查串口 ERPM、角度码和目标角与本轮组帧槽位一致。
6. 保持目标不变超过 1 秒，确认 `control_seen` 和 `link_valid` 仍为 1，解码目标保持不变。
7. 断开主控 CAN2，确认链路最多保持约 500 ms，随后 `link_valid` 和 `control_seen` 变为 0，最后目标值仍保留。
8. 重新连接主控，确认心跳恢复后 `link_valid=1`，但 `control_seen` 仍为 0。
9. 再次发送本组控制帧，确认 `control_seen=1`；修改本轮目标后目标更新。
